# VX RFCs

RFCs govern changes to VX language semantics, public APIs, compiler/runtime contracts, security boundaries, package formats, interoperability, and stable compatibility guarantees.

1. Copy `0000-template.md` to a four-digit number and descriptive slug.
2. Open a pull request with status `Proposed`.
3. Resolve design, compatibility, security, migration, and implementation questions.
4. A maintainer records `Accepted`, `Rejected`, or `Withdrawn` status.
5. Implementation begins only after acceptance, except for explicitly labeled experiments that expose no public contract.

Accepted RFCs are immutable records. Material changes require a superseding RFC.
